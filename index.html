01 · CONCEITOS E FUNDAMENTOS

Os primeiros passinhos ♡

As ideias que dão estrutura a um banco de dados bem cuidado.

▤　O que é banco de dados?＋

Conjunto estruturado de dados armazenados para consulta, atualização e gestão. Na escola, guarda alunos, cursos, turmas e notas com consistência.

✎　Dados, informação e banco＋

Dado: “Ana”. Informação: “Ana está matriculada em Redes, turma 2A”. Banco: estrutura persistente que organiza os dados usados para produzir informação.

⚙　O que é um SGBD?＋

Software que cria e consulta estruturas, controla concorrência, aplica restrições, gerencia transações e oferece recursos de segurança e recuperação.

✧　Vantagens de um banco＋

Centralização, menor redundância, integridade referencial, consultas combinadas, controle de acesso e manutenção organizada.

⌘　Entidades, atributos e relacionamentos＋

Entidade: algo sobre o qual mantemos dados (Aluno). Atributo: uma propriedade (email_aluno). Relacionamento: associação entre entidades (Aluno se matricula em Turma por meio de Matrícula).

02 · FORMAS DE ORGANIZAR

Dois jeitos de guardar dados ✿

Para esta escola, escolhemos o modelo relacional.

🌳MODELO 01

Hierárquico

Organiza registros como árvore de pais e filhos; cada filho costuma ter um único pai.

Escola
⌞━━━━┳━━━━┛
Curso ACurso BCurso C
turmas　　turmas　　turmas

Vantagem: leitura eficiente em hierarquias estáveis. Limitação: relações muitos-para-muitos e mudanças podem exigir caminhos rígidos.

Exemplo: pastas e organogramas.
🧸MODELO ESCOLHIDO

Relacional

Organiza dados em tabelas conectadas por chaves primárias e estrangeiras.

ALUNO
PK id_aluno1 ━ NMATRÍCULA
FK id_alunoN ━ 1TURMA
FK id_curso

Vantagem: integridade por PK/FK e consultas com JOIN. Atenção: precisa de boa modelagem e índices adequados.

Exemplo: cadastros escolares relacionados.

♡

MATRÍCULA resolve a relação muitos-para-muitos entre ALUNO e TURMA e guarda data e situação próprias.

⚠ Atenção a valor_nota: DECIMAL(2,2) não comporta 10,00. Para a escala de 0 a 10, considere DECIMAL(4,2), após confirmar o tipo real e aprovar a migração.
MYSQL · ESTRUTURA RESUMIDA
CREATE TABLE aluno (
  id_aluno INT PRIMARY KEY AUTO_INCREMENT,
  nome_aluno VARCHAR(120) NOT NULL,
  data_nascimento DATE,
  email_aluno VARCHAR(254) UNIQUE,
  telefone_aluno VARCHAR(24)
);
CREATE TABLE professor (
  id_professor INT PRIMARY KEY AUTO_INCREMENT,
  nome_professor VARCHAR(120) NOT NULL,
  email_professor VARCHAR(254) UNIQUE,
  telefone_professor VARCHAR(24),
  especialidade_professor VARCHAR(120)
);
CREATE TABLE curso (
  id_curso INT PRIMARY KEY AUTO_INCREMENT,
  nome_curso VARCHAR(140) NOT NULL,
  descricao_curso TEXT,
  cargahoraria_curso SMALLINT UNSIGNED NOT NULL
);
CREATE TABLE turma (
  id_turma INT PRIMARY KEY AUTO_INCREMENT,
  id_curso INT NOT NULL,
  id_professor INT NOT NULL,
  ano_letivo SMALLINT NOT NULL,
  semestre_turma TINYINT NOT NULL,
  turno_turma VARCHAR(20) NOT NULL,
  FOREIGN KEY (id_curso) REFERENCES curso(id_curso),
  FOREIGN KEY (id_professor) REFERENCES professor(id_professor)
);
CREATE TABLE matricula (
  id_matricula INT PRIMARY KEY AUTO_INCREMENT,
  id_aluno INT NOT NULL,
  id_turma INT NOT NULL,
  data_matricula DATE NOT NULL,
  situacao_matricula VARCHAR(30) NOT NULL,
  FOREIGN KEY (id_aluno) REFERENCES aluno(id_aluno),
  FOREIGN KEY (id_turma) REFERENCES turma(id_turma),
  UNIQUE (id_aluno, id_turma)
);
CREATE TABLE nota (
  id_nota INT PRIMARY KEY AUTO_INCREMENT,
  id_matricula INT NOT NULL,
  descricao_nota VARCHAR(140) NOT NULL,
  valor_nota DECIMAL(4,2) NOT NULL,
  data_nota DATE NOT NULL,
  FOREIGN KEY (id_matricula) REFERENCES matricula(id_matricula),
  CHECK (valor_nota BETWEEN 0 AND 10)
);

Exemplo didático, não executado no banco da escola. Confirme tabelas, view e regras de exclusão antes de migrar.

UMA JANELINHA PARA OS DADOS

Views: consultas que viram atalhos

Uma VIEW é uma consulta armazenada que apresenta dados de uma ou mais tabelas. Ajuda a reutilizar consultas e limitar as colunas oferecidas; não substitui as tabelas-base.

♡

A existência da view vw_alunos_cursos_turmas precisa ser confirmada no banco real.

VIEW · EXEMPLO MYSQL
CREATE VIEW vw_alunos_cursos_turmas AS
SELECT a.nome_aluno, c.nome_curso,
       CONCAT(t.ano_letivo, '-', t.semestre_turma) AS identificacao_turma
FROM aluno AS a
JOIN matricula AS m ON m.id_aluno = a.id_aluno
JOIN turma AS t ON t.id_turma = m.id_turma
JOIN curso AS c ON c.id_curso = t.id_curso;

SELECT nome_aluno, nome_curso, identificacao_turma
FROM vw_alunos_cursos_turmas;

FROM aluno a

JOIN turma t ON t.id_turma = m.id_turma
WHERE a.id_aluno = 1;
05 · GRANT (exemplo conceitual) 
GRANT SELECT ON escola.aluno
TO 'leitor'@'%';

Valores e usuário são exemplos didáticos, não registros reais. GRANT depende do SGBD e deve ser aplicado por um administrador com privilégio mínimo. DELETE também deve usar filtro e ser autorizado; nunca execute exemplos contra produção sem revisão.

07 · FECHANDO COM CHAVE DE OURO

Dados organizadinhos,
escola mais preparada. ♡

Um banco relacional substitui listas desconectadas por registros relacionados. Chaves e restrições ajudam a preservar integridade; consultas reúnem informações úteis; permissões e cópias apoiam proteção e recuperação dos dados.

Para este protótipo acadêmico, recomendamos PostgreSQL: é open source, extensível, multiplataforma e oferece recursos relacionais sólidos sem custo de licença do servidor. Hospedagem, capacitação, operação e suporte ainda têm custos. Se a escola já depender de outro ecossistema, isso pode mudar a recomendação.
